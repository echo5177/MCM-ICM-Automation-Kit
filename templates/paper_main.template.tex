\section{Assumptions and Justifications}

\section{Notation}
[Symbols with units. Define each symbol again where it first appears.]

% One section per requirement, each complete in itself. A judge looking for the answer to
% Task 2 should not need Task 1's section or a separate "Results" chapter. Copy this block
% for every requirement in reports/requirements.csv.
\section{Task 1: [what it answers]}
\subsection{What the Task Turns On}
[The `turns\_on' sentence from the requirement table: the trade-off or the quantity that
decides the answer. Then why the model below suits it.]

\subsection{Data and Parameters}
[Where each number comes from: a cited source, the problem's data, or a stated
assumption (reports/param\_ledger.csv).]

\subsection{Model}
[Start from the simplest model that produces a number. Add a component only where the
model ladder (reports/model\_ladder.csv) shows that it wins, and print that comparison.]

\subsection{Results}
[The answer first, with its number and unit, traceable to key\_results.csv. Then the
figure or table that carries it, then what it means for the decision.]

\subsection{Check}
[Against the baseline, against held-out data, or against a relation you know.]

\section{Sensitivity Analysis}
[Vary the assumptions you made, one at a time, over a range you can defend. Show the
response in a figure. End each part with a consequence, not with ``the model is robust''.]

\section{Strengths and Weaknesses}
[Two or three of each, specific to this model. State each limitation once, here.]

\section{Recommendations}
[Decisions, not topics: the action, the model threshold that triggers it, the quantified
effect. If the problem asks for a letter or memo, give it its own section instead:
bottom-line results for its reader, no equations, signed ``Team \#'' and the control number.]

\section{Conclusion}
[The answer to each requirement, in one sentence each.]
